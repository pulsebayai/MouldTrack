## Deviations from plan
- Spec says new actions "rely on 04's format rule"; replaced by the PR #6 registry (03 inserts its own actions).

- Step 1: `phone_claim` lives in schema `app` (not exposed by PostgREST, no client grants) instead of `public`. The SA `tenant` select policy inlines the platform_admin check instead of calling `app.is_platform_admin()`: 02's test 004 forbids any client-executable `app` function besides the two RLS helpers. `app._ua_dupcheck` was redefined (additive) to read `phone_claim`, so 02's duplicate-phone message also covers Super Admin phones. Local pgTAP harness (PG16 + pgTAP via apt, mocked auth schema) runs 001-006 + 020 green; CI `db` is still the proof.
- Step 2: setup serialisation uses `pg_advisory_xact_lock` instead of a singleton row (same effect, no extra table). Setup refusals are audited at most once per minute (public endpoint: unbounded audit writes would be a flooding vector); the setup audit row has `source = 'edge:platform-setup'`, null actor. Added a fourth read function `public.pa_super_admins()` (the Super Admins screen needs it; SAs have no RLS access to other platform_admin rows). Unknown tenant/SA targets raise `guard` with field `not_found` (SA is an authorised actor, so no existence-leak concern); an SA targeting a supervisor or unknown user in `pa_ua_reset_password` is a denial. 021 has 153 assertions.
- Step 3: `app._ua_authorise` (02) is redefined additively so an SA caller is denied with reason/role `platform_admin` (02's R8 body otherwise unchanged); 04's `pm_*` functions should copy this branch so SA denials reach the platform audit. 022 discovers tenant-owned tables from `information_schema` (any public table with `tenant_id`), asserts RLS enabled + forced on each and that an SA reads 0 rows from each. The `pm_*` denial assertions are added at step 8 after the rebase.
- Step 4: `platform-setup` token check lives in `_shared/setup-token.ts` (pure TS, Jest-tested: unset/short/wrong/right) so the "no token configured" refusal is proven in unit tests, because the local stack always has the config.toml token; the hosted check (step 9) covers "unset on dev". The local token is a non-secret literal in `supabase/config.toml [edge_runtime.secrets]` (if `supabase start` does not pass it to the edge runtime, CI shows it and the fallback is an env step in ci.yml). `platform-setup.spec.ts` runs in a new Playwright project `api-setup` (depends on `api` and `e2e`, ignored by the `api` project) because it empties `platform_admin`; it restores the fixture SAs afterwards and skips on non-local targets. `service_role` got DML on `platform_admin` (fixtures, like membership). The `account` function branches on the caller's own `platform_admin` row (service client select), calling `psvc_pa_password_changed` for SAs; tenant users take the unchanged 02 path. New `_shared/auth-users.ts` (additions only); `user-admin` untouched. SA fixture helpers (`provisionSuperAdmin`, +91 90000 00090/91) were added to `e2e/api/helpers.ts`; API specs use `orgDef(7)` (8 and 9 are reserved for 04).
- Step 5: fixtures are additions only (existing exports `TENANTS`/`USERS` are pinned by 02's tests, so Super Admins and plan labels are new exports `SUPER_ADMINS` / `TENANT_PLANS` / `TEST_TENANT_PREFIX`). `orphan-check.ts` and `consistency-check.ts` mains now also read `platform_admin` (otherwise the nightly hosted-checks would flag the fixture Super Admins as orphans); their pure functions and tests are unchanged. `fixtures-reset` suspends `e2e t3 %` tenants.
- Step 6: `loadSessionContext` (new) wraps 02's `getSessionContext` and falls back to a platform lookup only when the membership path yields no access, so 02's session tests (one `.eq` call) stay unchanged. Console screens live in a new `(console)` route group with its own guard layout. Screen tests mock the `@/lib/platform` fetchers/`platformApi` rather than a fake RPC layer. Found while testing: validating the time zone against `Intl.supportedValuesOf` rejects aliases such as `Asia/Kolkata` (Chrome lists `Asia/Calcutta`), so the form now validates with `Intl.DateTimeFormat` (`isKnownTimezone`); the server still validates authoritatively.
- Step 7: `console.spec.ts` finds the tenant row id through the service client (the tenant name is unique per run) and opens its detail from the list; created Unit Admins are removed in `afterAll`, test tenants stay (never deleted: audit rows reference them) and are suspended by `fixtures-reset`. The `/plant` route does not exist on this branch (04 owns it), so the SA-blocked check covers `/home` and `/users` only; add `/plant` at step 8 after the rebase. The console navigation uses `role="navigation"` (axe rejected `role=menu` without menuitems). Web e2e could not run locally (no Docker); CI on PR #9 is the proof.
