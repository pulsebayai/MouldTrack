## Deviations from plan
- Step 2: SDK 58 template uses `src/app/` (Expo Router) + `src/lib/`, not root `app/`; paths in "Files that change" read as `src/...`. Reason: template default; no design impact.
- Step 2: `build` = `expo export -p web && scripts/android-prebuild-check.sh` (prebuild on a throwaway copy) instead of prebuild in place. Reason: prebuild rewrites package.json and the device mount refuses `android/gradle/wrapper` (EACCES).
- Step 2: Jest config lives in package.json (`jest` key, jest-junit reporter) instead of jest.config.js.
- Step 2 (device only): `node_modules` is a symlink to VM-local `$HOME/nm/node_modules` — writing node_modules into the Mac folder is too slow (install never completed in 12 min vs 10 s locally). Gitignored; on a real dev machine/CI run plain `npm ci`. Expo's compatibility API is blocked from the device, so native module versions were taken from `expo/bundledNativeModules.json`.

- Step 4: proof run on a stand-in (Postgres 16 in the cloud workspace + pgTAP + a shim of Supabase roles/auth/extensions and default grants): 18/18 pgTAP pass; mutation check (policy loosened to `true`) makes tests 5 and 12 fail as intended. The real Supabase run is still required in CI (step 8). Reason: no Docker on the device.
- Step 6: screen tests live in `src/__tests__/screens/` (files under `src/app/` become routes). Session state via `SessionProvider` (`src/lib/session-provider.tsx`) driven by Supabase `onAuthStateChange` incl. `INITIAL_SESSION` (lint rule forbids setState directly in effects; deferred with setTimeout per Supabase guidance). Scaffold placeholder test `harness.test.tsx` removed because the placeholder screen it rendered no longer exists; superseded by screen tests (no behaviour test was weakened).
- Step 6 (device): the MouldTrack folder appears to be iCloud-synced (a `dist 2` conflict copy appeared and empty `dist/` cannot be removed). `build` now takes `WEB_DIST` (default `dist`); local runs export outside the folder. `dist*/` gitignored.
